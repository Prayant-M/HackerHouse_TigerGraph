## 2. TigerGraph credentials you must generate

### If using Savanna

1. Sign in, create an **organisation**, then a **workspace**. Pick the smallest tier that gives you TigerGraph **4.2+** (this is non-negotiable — TigerVector and hybrid retrieval do not exist below 4.2).
2. In workspace settings, **enable auto-stop and auto-start**. The brief explicitly requires this.
3. Create a database user with the **superuser** role for loading and query installation. Do not use it from the UI at runtime — create a second, lower-privilege user for the agent's read path if you have time.
4. Collect: workspace host URL, username, password, graph name, and (recommended) a **secret** and **token** for API auth.
5. Note the RESTPP and GSQL ports your workspace exposes. On a default CE install these are 14240 (nginx/GSQL) and 9000 (RESTPP); Savanna fronts everything behind one HTTPS host.

### If using Community Edition locally

You need Docker with at least **8 CPUs and 20 GB RAM allocated** (the documented minimum is 4 CPUs / 16 GB and it is genuinely painful at that level with 590k transactions). Create a DBA user with the superuser role and set a password before connecting MCP.

CE limits: single server, and up to ~300 GB combined graph + vector storage on 4.2.1+, with vectors capped at 4096 dimensions. You are far under all of these.

## 3. API keys — what to get and how much to budget

### Primary LLM (pick one, get a second as fallback)

| Provider | Key variable | Get it at | Notes |
|---|---|---|---|
| Anthropic | `ANTHROPIC_API_KEY` | `console.anthropic.com` | Strong tool-use and long-context synthesis; the TigerGraph MCP chatbot example supports the Anthropic model family directly |
| OpenAI | `OPENAI_API_KEY` | `platform.openai.com` | Also covers embeddings with the same key — one fewer account |
| Google | `GOOGLE_API_KEY` | `aistudio.google.com` | Generous free tier; useful as the fallback |

**Budget realistically.** A full 20-case benchmark run with a 3-round loop is roughly 60–120 LLM calls with substantial context. Assume ~$8–20 per full run before caching. You will run it 10–20 times during development. **Budget $80–150 total**, and cut it by 70% with the response cache described in `04` Phase 4. Set a hard spend limit in the provider console on day one.

### Embeddings

| Option | Key | Dim | Cost | Recommendation |
|---|---|---|---|---|
| OpenAI `text-embedding-3-small` | `OPENAI_API_KEY` | 1536 | ~$0.02 / 1M tokens | Default choice — cheap, good, one key |
| Voyage `voyage-3` | `VOYAGE_API_KEY` | 1024 | Paid | Strong retrieval quality |
| Local `sentence-transformers/all-mpnet-base-v2` | none | 768 | Free | Zero-key, fully offline, perfectly adequate here |

You are embedding a few thousand short case narratives and policy chunks, not a corpus. If you want to remove a dependency, **go local** — the quality difference on this task is marginal and it makes your repo runnable by a judge without any embedding key at all. That last point is worth more than a small accuracy delta.

Whatever you pick, **fix the dimension before you write the DDL.** Changing embedding dimension means dropping and recreating every vector attribute.

### Optional keys

| Service | Variable | Why | Needed? |
|---|---|---|---|
| LangSmith | `LANGCHAIN_API_KEY`, `LANGCHAIN_TRACING_V2=true` | Trace visualisation for blog screenshots and loop debugging | Strongly recommended |
| Vercel | `VERCEL_TOKEN` | Deploy the UI if you want a live link | Optional |
| Twilio / SendGrid | `TWILIO_*` / `SENDGRID_API_KEY` | "Real" simulated customer outreach | Not recommended — see §6 |
| IPQualityScore / emailrep | `IPQS_API_KEY` | External identity/IP reputation | Not recommended — see §6 |

## 4. Complete `.env.example`

Commit this file with empty values. Commit `.env` to `.gitignore`. Verify with `git check-ignore -v .env` before your first push — an accidentally committed key in a public hackathon repo is a bad day.

TG_GRAPH_NAME=FraudGraph
TG_USERNAME=

TG_TOKEN=                         # generated from TG_SECRET, short-lived

# ─── LLM ──────────────────────────────────────────────────────────────

## 5. Local environment

| Requirement | Version | Note |
|---|---|---|
| Python | ≥ 3.12 | TigerGraph MCP requires 3.12+ |
| Node.js | ≥ 20 | For the Next.js console |
| Docker | latest | Only if running Community Edition |
| RAM | 16 GB minimum, 32 GB comfortable | CE alone wants 20 GB |
| Disk | ~20 GB free | Dataset, staged CSVs, graph storage |

Python packages: `pyTigerGraph`, `tigergraph-mcp`, `langgraph`, `langchain-core`, the provider SDK you chose, `pandas`, `pyarrow`, `scikit-learn` (PCA + calibration), `sentence-transformers` if going local, `pydantic`, `fastapi`, `uvicorn`, `networkx` (motif mining), `matplotlib` (calibration plots).

Install the MCP server and verify:

```bash
pip install tigergraph-mcp
tigergraph-mcp --env-file .env -vv
```

Then confirm from Python that `tigergraph__list_graphs` returns your graph. If that call fails, nothing downstream will work — fix it before writing agent code.

You can narrow which MCP tools the agent sees with `TG_ALLOWED_TOOLS` / `TG_BLOCKED_TOOLS`. Do this. Fifty-plus tools in the context degrades tool selection noticeably; expose the ten or so the agent actually needs plus your custom fraud tools.

## 6. Decisions only you can make

### Savanna or Community Edition?

**Load and develop on CE locally, demo on Savanna.** CE gives you fast iteration and shell access for `gadmin`; Savanna gives you a stable hosted instance for the video and a link a judge can be shown. Loading 590k transactions repeatedly over the network into Savanna will waste hours. Note that Savanna is fully GUI-based with no shell — GSQL goes into the Savanna editor and runs from there.

### Which LLM?

One good tool-use model plus a cheap fallback. Don't build multi-model routing unless everything else is done — it is a `06` nice-to-have (D12), not a rubric item.

### Real external APIs, or stubs?

**Stubs.** The IEEE-CIS data is fully anonymised — `card1` is a surrogate integer, email domains are coarse categories, there are no real IPs or phone numbers. A real IP-reputation or email-breach lookup has nothing to look up and would return noise. Build `mcp_servers/simulated_actions/` as a deterministic mock service, document clearly in the README and blog that these are simulated, and note that the brief explicitly permits it: *"Actions such as sending customer messages, freezing accounts, blocking cards, refunding customers, updating CRM systems, or closing cases may be simulated, stubbed, or represented through mock APIs."*

Honest stubs beat fake integrations. Judges at a graph database company have seen a lot of fake integrations.

### Do you extend the dataset?

The brief allows it. The highest-value extension is **not** external data — it is derived structure you compute yourself: the `CO_OCCURS_WITH` projections, community/hub attributes, behavioural embeddings, and the empirical likelihood-ratio table. All of these are "extending the dataset" in the way that actually improves investigation accuracy, and none of them require a key.

## 8. Day-one 30-minute checklist

Do this in one sitting, today, before any design work. Every item is a blocker with an external dependency, and finding out on day six that your workspace is on 4.1 is a project-ending discovery.

1. Create the Savanna workspace; confirm the version string reads **4.2 or higher**.
2. Enable auto-stop and auto-start.
3. Create the DBA superuser; store the credentials in `.env`.
4. Download the HHGOA dataset; confirm you can open the README and every file listed in it.
5. Get the LLM API key; set a hard spend cap in the provider console.
6. `pip install tigergraph-mcp`; run it against the workspace; successfully call `tigergraph__list_graphs`.
7. Create the public GitHub repo with `.gitignore` covering `.env`, `data/raw/`, `data/staged/`, `.cache/`.
8. Join the Discord and the WhatsApp group.

If item 6 fails, that is your entire day one. It is still the right day one.
