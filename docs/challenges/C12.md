# C12 — Schema drift survival

**Depth:** medium

`ingest/00_drift.py` diffs every old/new file pair present (columns added/removed, renames proposed by the schema mapper with sample records, dtype / null-rate / range / category shifts, key overlaps), names what each change breaks downstream (which query, signal or calibration), writes a proposal, and **exits 4 until a fraud manager approves** it with a token; the approval is signed into the ledger and written to the graph as a `SchemaChange` vertex, and the data manifest (sha256 per raw file) that feeds every attestation's `data_snapshot` is regenerated. Loaders read every month present (`PATHS.transaction_files()`), and `07_verify` fails loudly if any case-pack or closed-case card id does not resolve. The January files were not in this repository's data folder at the time of the run, so the gate reports "nothing to gate"; it was rehearsed on a renamed and reshaped variant.

**Attested:** The before/after shape of what changed, what broke, and the approved re-mapping (`data/drift/DRIFT-*.json`).

**Numbers:** `eval/reports/drift.md` (generated by the run, never typed here).

**Reproduce:** `make drift`
