# C07 — Containment planner

**Depth:** deep (Innovation 2)

Backward and forward. `ring_at_asof` cuts the card-device co-occurrence at as_of and takes the seed's component (time-sliced WCC). The block set blocks only cards on which fraud is established, smallest set covering 90% of their attested exposure, with each L1/L2 route and every customer touched named; hit-but-unproven cards get step-up, never a block (R1); BLOCK_ALL_CARDS is never proposed (R10 stays with the policy engine). Forward: cards that touched the compromise origin and are not yet hit get MONITOR_CARD + STEP_UP_AUTH on the next card-not-present purchase, and a WATCH child case. The origin is written back as a `COMPROMISE_POINT` edge and later investigations read it through `compromise_watch`.

Measured on rings from the closed history (the history names only 4 explicit rings, so rings are also implied by shared rare devices): see the table. Honest reading: matched controls are what make the origin usable (raw counts drown in popular entities), and a narrow-entity cap was added after the first run showed region-level "origins" flagging hundreds of innocents; both runs are reported. Plain fan-out over *rare* devices scores higher precision on these rings — but these rings are defined by a shared rare device, so that baseline is favoured by construction.

**Attested:** Each plan shows the exposure it cuts, with amounts, and names the customers it touches; origin, at-risk and block-set numbers each carry an attestation over the query that produced them.
