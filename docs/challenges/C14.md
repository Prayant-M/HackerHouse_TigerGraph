# C14 — Case management

**Depth:** medium

A case is a record with a life. Each run writes state changes (OPENED → AWAITING_EVIDENCE → ESCALATED / PENDING_APPROVAL / CLOSED_*) with the evidence that caused each and who acted, as `CaseStateChange` vertices through `case_write`; every human approval appends a transition (`data/lifecycle/<case>.jsonl`, versioned across sittings, flagged when a rerun changed the decision). At-risk ring cards get WATCH child cases (`CHILD_CASE` edges). The **Case life** tab shows the handover note an analyst needs to pick the case up cold: state, what it waits on and whose approval, what the agent already did, open questions, what changed.

**Attested:** Every state change records the evidence that caused it, when it happened, and who approved it where policy required approval.

**Numbers:** console → case → Case life; `GET /api/lifecycle/{case}` (generated by the run, never typed here).

**Reproduce:** `make case CASE=<id> then approve in the console`
