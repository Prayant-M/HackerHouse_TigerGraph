How it works

From alert to explained decision in five steps

The AI plans and writes the explanations. The decisions come from the graph and the bank's policy, in code the AI can't touch.

  1. ⚡

    Alert arrives

    From the bank's risk model, a customer saying "that wasn't me", or an analyst's question.

  2. 🕸️

    Search the graph

    Cards, devices, regions and past behaviour, all capped at the alert's timestamp. No peeking into the future.

  3. 🧠

    Recall past cases

    Finds similar closed investigations by meaning and by shared cards or devices, in one TigerGraph query.

  4. ❓

    Ask only if worth it

    Unsure? It recommends a safe first step, then picks the question with the most information per unit of customer hassle.

  5. ✅

    Decide & explain

    Final actions with the policy rule cited. Blocks and filings wait for a human to approve.

Why TigerGraph

Some fraud only exists as a shape in the graph

🔗

Hybrid memory in one query

Vector search over 5,565 past case narratives, fused with a traversal to the cases that touched the same cards and devices, in a single GSQL query.

🧮

Graph algorithms find the ring

WCC and PageRank from TigerGraph's GDS library run on the anonymous-proxy slice of the card network. The HHG-014 ring is its own 54-card component; ordinary cards stand alone.

🧩

Every case becomes part of the graph

Each investigation is written back as a FraudCase linked to its evidence, decisions and actions, so the next analyst can find it.

🛡️

Guardrails the AI can't argue past

Probabilities, actions and approval routes come from deterministic code. A test fails the build if that code ever imports an AI model.
