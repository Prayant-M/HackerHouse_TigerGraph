# What you need to provide

Everything on this page is something **only you** can create, obtain, or decide.
Nothing here can be generated by code in this repository.

**Read this first:** the repo already runs end to end with none of it. With an
empty `.env` the graph layer uses the local mirror over the staged parquet and
the agent writes its prose from deterministic templates. The verdicts, the
probabilities, the actions and the approval routes are bit-identical either way
— only the wording of the narratives and the storage backend change. So you can
verify the whole pipeline before spending a rupee, and you can hand a judge a
repo they can reproduce without any credentials at all.

What the credentials buy you: the submission requires TigerGraph, and the demo
is better with an LLM writing the narratives.

## 0. The five-minute version

If you do nothing else, do these in order:

1. Create a **TigerGraph Savanna** workspace — confirm the version reads **4.2
   or higher**, and turn on auto-stop/auto-start. (§2)
2. Put its host, username and password into `.env`. (§2)
3. Get **one LLM API key** and set a hard spend cap in the provider console. (§3)
4. Create the **public GitHub repo** and push. (§5)
5. Record the **demo video**, write the **blog post**, make the **social post**. (§6)

Items 1–2 are the only ones with an external dependency that can bite you late.
Do them today.

## 2. TigerGraph credentials

### Savanna (recommended for the demo)

1. Sign in, create an organisation, then a workspace.
2. **Check the version string reads 4.2 or higher.** This is not negotiable:
   `graph/ddl/02_vectors.gsql` uses TigerVector, and `hybrid_case_recall` — the
   query this whole project is built around — does not exist below 4.2. Finding
   this out on day six is a project-ending discovery.
3. In workspace settings, **enable auto-stop and auto-start**. The challenge
   brief explicitly requires it.
4. Create a database user with the **superuser** role for loading and query
   installation.
5. Collect the workspace host URL, username and password.

Put them in `.env`:

```bash
TG_HOST=https://your-workspace.i.tgcloud.io
TG_GRAPH_NAME=FraudGraph
TG_USERNAME=your_user
TG_PASSWORD=your_password
# optional but preferred for API auth:
TG_SECRET=
```

Then:

```bash
python ingest/06_stage_graph_csv.py     # writes the CSVs the loading jobs read
python graph/install.py --step all      # schema, vectors, load, queries, GDS, verify
```

`--step verify` is the one to watch. TigerGraph builds the HNSW index
asynchronously, and vectors that have not finished indexing silently return no
search results. RESTPP also accepts a misspelled vector attribute name without
error and hands you an empty index. Both failure modes look exactly like "the
agent found no similar prior cases", which is the worst possible way to find
out. The verify step polls for this and asserts non-zero counts.

### Community Edition (local fallback)

Docker with **at least 8 CPUs and 20 GB RAM allocated**. The documented minimum
is 4 CPUs / 16 GB and it is genuinely painful there with 590k transactions.
Create a DBA user with a password before connecting.

```bash
TG_HOST=http://localhost
TG_USERNAME=tigergraph
TG_PASSWORD=your_password
```

**Recommended split:** load and iterate on Community Edition locally, demo on
Savanna. Loading 590k transactions repeatedly over the network wastes hours.

## 3. API keys and budget

### LLM (pick one; a second as fallback is nice, not required)

| Provider | Variable | Get it at |
|---|---|---|
| Anthropic | `ANTHROPIC_API_KEY` | `console.anthropic.com` |
| OpenAI | `OPENAI_API_KEY` | `platform.openai.com` |
| Google | `GOOGLE_API_KEY` | `aistudio.google.com` (generous free tier — good as the fallback) |

```bash
LLM_PROVIDER=anthropic
LLM_MODEL=claude-sonnet-5
ANTHROPIC_API_KEY=sk-ant-...
```

**Budget.** A full twenty-case run makes roughly 40–60 model calls: one tool
plan, one case summary, one SAR narrative per filing case, one pattern
description per undocumented case. Expect **well under $1 per full run**, because
the model is not in the reasoning loop — it never re-reads the graph, never
iterates, and every prompt is a short structured brief rather than a dump of
transaction rows.

Responses are cached on disk by prompt hash (`.cache/llm/`), so a re-run of the
benchmark costs nothing and produces byte-identical prose. **Budget $20 and set
a hard spend cap in the provider console on day one** — that is ample, and the
cap protects you from a loop bug.

### Embeddings — nothing to buy

Default is `EMBEDDING_PROVIDER=auto`: it uses `sentence-transformers/all-MiniLM-L6-v2`
if the weights are reachable, and otherwise falls back to a TF-IDF + truncated-SVD
model fitted on the corpus itself, which downloads nothing and is byte-reproducible.
Both are 384-dimensional, matching the DDL.

If you want to swap in a paid embedding model, **fix `EMBEDDING_DIM` before you
load anything** — changing it means dropping and recreating every vector
attribute in the graph.

### Deliberately not used

| Service | Why not |
|---|---|
| Twilio / SendGrid (real customer messaging) | The brief explicitly permits simulated outreach, and the data is anonymised — there is no one to message |
| IPQualityScore / emailrep (identity & IP reputation) | `card1` is a surrogate integer, email domains are coarse categories, and there are no real IPs. A live lookup returns noise dressed as evidence |

`src/fraudagent/mcp_servers/simulated_actions.py` stubs these deterministically
and says so in every receipt it writes. An honest stub beats a fake integration,
and judges at a graph database company have seen a lot of fake integrations.

```bash
python -m pip install -r requirements.txt
```

### The dataset

The HHGOA dataset is **not** committed — `transactions.csv` alone is 676 MB.
Download it and place the four files here:

```
Datasets/
├── transactions.csv            590,742 rows
├── identity.csv                144,432 rows
├── closed_cases_history.csv      5,565 rows
├── case_pack.csv                    20 rows
└── README.md                   the dataset's own documentation
```

`python ingest/07_verify.py` will tell you if anything is missing or wrong.

## 5. Repository and submission

```bash
git init
git add .
git commit -m "TigerGraph agentic fraud investigation"
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

**Before pushing, confirm the secret file is ignored:**

```bash
git check-ignore -v .env      # must print a .gitignore line
```

An API key committed to a public hackathon repo is a bad day.

The submission form is strict about one thing in particular: the twenty answer
files must be in a folder named `cases/` at the repo root, named exactly
`HHG-001.json` … `HHG-020.json`. `python benchmark/run_20.py` writes them there
and validates every one against the dataset's Answer Format before it finishes.

## 7. The decisions only you can make

**Savanna or Community Edition for the demo?** Savanna, with CE as the local
fallback. Savanna gives you a link a judge can be shown; CE gives you fast
iteration. The code runs against either — `GRAPH_BACKEND=auto` picks TigerGraph
whenever credentials are present, and falls back to the local mirror with a
printed warning if the workspace is unreachable, so an auto-stopped workspace
cannot kill your demo mid-recording.

**Which LLM?** One good tool-use model. Do not build multi-model routing; it is
not a rubric item and the model is not on the critical path here.

**Do you extend the dataset?** The brief allows it. This repo already does, in
the way that actually improves accuracy: the `CO_OCCURS_WITH` projection, the
64-dimensional behaviour embeddings, the measured likelihood-ratio table and the
two undocumented typologies mined out of the closed cases. None of those need an
external source. Adding one would add risk without adding evidence.

**Do you run the autonomous sweep?** `python benchmark/monitor.py` is optional
and counts toward Innovation, not accuracy. It writes to
`benchmark/autonomous/`, never to `cases/`. It is worth running — two of its
three triggers find cases the bank's own risk model does not score highly at all.
